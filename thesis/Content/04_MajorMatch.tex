
\chapter{MajorMatch}

\section{The Interest Elicitation Problem}

While many existing career and program recommendation systems exist, those commonly used by educational systems require significant effort from the student. In practice, these quizzes, while robust, essentially ask the students to reveal preferences and insights about themselves they may not know. Therefore, the challenge with MajorMatch is to create a system that provides useful program recommendations while minimizing the mental effort on the students' side.

For example, MajorMatch extends the TopProRec approach by replacing the open-ended topic browsing step with a more structured interest input. Through a series of three quiz formats (described as games to users) the user is kept engaged while providing valuable data. This approach balances the cognitive load on users, engagement, and value of the data capture. In addition, MajorMatch implements a two stage matching system where users are first matched to clusters of majors.

\section{System Design}

MajorMatch operates in two stages. Stage 1 uses responses to Games 1 and 2 to select the top 1--4 clusters that match the student's interests. Stage 2 uses Games 2 and 3 to select up to 3 programs from each matched cluster, each with a confidence score.

The structured approach of the matching system allows for some interpretability since each recommendation is traceable to a cluster match. Cluster and program selection are done via API calls to a Large Language Model (LLM). 

The default dataset includes 106 popular majors across the United States, organized into 8 clusters: Law, Justice \& Public Policy; Creative Arts \& Media; Business \& Management; Engineering \& Technology; Health \& Behavioral Sciences; Sciences \& Mathematics; Education \& Teaching; and Humanities \& Cultural Studies. Full cluster descriptions appear in Appendix~\ref{app:clusters}. Clusters were derived through a mixture of hand-selection and embedding clustering.

\section{Interest Elicitation via Structured Games}

MajorMatch collects student preferences through three games, each serving a distinct role in the matching pipeline.

\textbf{Game 1: Fact or Fiction} presents eight binary statements, one per cluster. Students mark each as true or false for themselves. Any cluster they reject is filtered out of the candidate set. The statements are designed to surface broad alignment with a field (see Appendix~\ref{app:games} for the full list).

\section{Deployment and Iteration}

The current version of MajorMatch represents the sixth iteration developed over several months. Each revision was driven by qualitative feedback, retention rates, and thumbs up/down responses. The latest version has been used more than 950 times. Timed variants, alternative gamification elements, and alternate question sets were evaluated and discarded across iterations in favor of the current design.

The core framework has been extended to custom deployments, including a careers-focused variant and university-specific versions that link recommendations back to actual catalog offerings. The embedding analysis in Chapter 3 motivates this extensibility: because program embeddings recover human-defined conceptual groupings, clustering on a new catalog automatically produces a principled starting point for cluster construction without manual labeling. While additional analysis was used in the default dataset, Chapter 3 demonstrates how automatic clustering can provide a meaningful starting point.

The overall goal of MajorMatch is to demonstrate how a recommendation system can reduce elicitation burden without sacrificing relevance. By leveraging embedding structure and LLM capabilities MajorMatch can easily adapt to new datasets with minimal effort while providing valuable recommendations.
